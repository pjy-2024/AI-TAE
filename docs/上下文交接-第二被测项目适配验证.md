## 一、这个任务要证明什么（一句话）

**换一个不同的真实被测项目，只写适配器、不改核心代码，V1 就能真实跑通并出数字** —— 把「适配层可移植」从声称变成实证。

## 二、验收标准（做完才算）

1. 选定第二个真实项目并固定 commit（clone 到 data/targets/<项目名>，gitignore 不入库）；
2. 新增 `src/aiae/targets/<项目>.py` 适配器并注册（AITAE_TARGET 指向它）；
3. **核心代码零改动**下：`aiae generate` + `aiae run` 真实跑通，出真实数字（可执行率/通过率，记录在 progress 对应日期）；
4. 若第二个项目暴露「适配接口不够用」，扩展的是 **targets 适配契约**（见 §五），不是给核心加 if 分支；
5. 记录踩坑与「换项目成本」（改了哪几个文件、每处原因）→ 面试素材。

## 四、TargetAdapter 接口速记（写新适配器要实现的）

```python
class TargetAdapter(ABC):
    name: str                     # AITAE_TARGET 用的名字
    auth_role: str = "user"       # registered_user 角色（todo 用 admin 通吃普通+admin）
    default_base_url: str = "http://127.0.0.1:8000"
    resource: ResourceAdapter | None = None   # 无资源 id 语义的项目 = None

    def register_user(self, base_url, *, role) -> dict   # 注册随机用户返回凭据
    def login_token(self, base_url, username, password) -> str

class ResourceAdapter(ABC):
    fixture_name: str             # 如 todo 的 "created_todo_id"
    def create_id(self, base_url, headers, seed) -> int  # 创建资源返回 id
```

## 五、换项目前必须补的「适配接口」缺口（上一阶段诚实遗留）

> 这些不是 bug，是「todo 假设」还没参数化完。新对话任务之一就是补它们，
> 补法：**扩展 targets 契约 + 让核心读契约**，而不是在核心写 if。

1. **generator 的 Prompt 指令硬编码**：`_interface_instruction` 写死了
   `fresh_user`（登录类）和 `created_todo_id`（资源 id 类）的文案 —— 它假设被测有「登录 + 资源 id」。
   补法：`TargetAdapter` 增加「能力描述」方法（如 `has_auth` / `resource.describe_for_prompt()`，
   base 里已有 describe_for_prompt），generator 从 adapter 取文案/开关。
2. **conftest 假设有「注册/登录」**：runner 模板固定生成 registered_user/auth_headers/fresh_user。
   无认证项目应退化（不生成这些 fixture；生成用例也不需要）。补法：TargetAdapter 加
   `auth_mode: "password" | "apikey" | "none"` 之类，模板按 mode 渲染。
3. **cli 缺省路径写死 todo_app**：cli._DEFAULT_OPENAPI、report 标题「被测项目 todo_app」。
   补法：从当前 adapter 读（get_adapter().openapi_relpath / .name）。

## 六、第二个被测项目选型（建议，可与本人确认）

- 目标：**比 todo_app 更简单 + 认证形态不同**，验证框架能退化。
- 推荐方向（按验证价值排序）：
  a. 无登录的纯 API CRUD 项目（FastAPI/Flask，自带 OpenAPI）→ 验证 auth_mode="none" 退化；
  b. 带 API-Key 或不同认证的项目；
  c. 同栈另一 FastAPI 项目（验证价值最低，仅作兜底）。
- 约束：能真实跑（pip 依赖少、一条命令起服务、有 OpenAPI 可导出）、固定 commit。
- 注意：clone 需要网络（要用户批准）；被测项目 venv 独立创建（C 盘独立 Python 3.12，依赖按项目自身 lock 时代版本，勿追最新——依赖漂移教训）。

## 七、步骤清单（建议顺序）

1. 选型 + clone 固定 commit 到 data/targets/<项目> + 建独立 venv + 起服务验证 /openapi.json 或等价导出；
2. 写适配器 `src/aiae/targets/<项目>.py`（继承 base；无认证 → auth 相关方法返回/抛 NotImplemented 或按 §五 先补契约）；注册；`get_adapter("<项目>")` 验证；
3. 补 §五 缺口（generator/conftest/cli 读适配契约）；**先跑 todo_app 回归**（AITAE_TARGET=todo_app 时 19/19 不破）；
4. AITAE_TARGET=<项目> 真实 generate + run → 记录真实数字；
5. 记录换项目成本（改了哪些文件/为什么）→ progress 新日期 + 面试文档更新；
6. 全程真实数字纪律；commit 由本人执行（沙箱不能写 .git）。
