## 一、本阶段完成的事（全部真实，2026-09-05）

### 1. 生成质量根治：方案 B（资源能力与认证形态解耦）
- 背景：fastapi_crud_todo（无认证）第一轮通过率 66.7%，2 例失败=LLM 用例自建资源后凭 REST 惯例断言 201（被测实际 200）。
- 尝试①：Prompt 加「状态码纪律」规则 → 通过率反而 50%（LLM 看不到自建子请求对应接口的 responses，规则缺信息支撑，只能猜）。
- 结论：与其让 LLM「少犯错」，不如让 LLM「没有机会犯那类错」。
- 方案 B：无认证项目也可声明 resource，由框架创建资源 fixture（created_todo_id）注入用例 → LLM 不再自建 → **通过率 100%（6/6，零人工修正）**。
- 改动：src/aiae/targets/fastapi_crud_todo.py（+ResourceAdapter）、runner conftest none 形态支持资源 fixture、generator none 形态对 id 类接口给 fixture 指令、base 契约 docstring；todo_app 回归 19/19 不破；自身测试 147 通过。
- 三轮真实对比（同一被测、同一模型、无人工修正）：66.7% → 50% → 100%。

### 2. 回归有效性实证（bug 演示）
- 在 fastapi_crud_todo 快照制造「悄悄错」：create 存库前把 title 污染（返回仍 200、有 id，人肉一眼看不出）。
- 测试抓到：test_create_todo 断言 title 一致性 → 红（5/6）；还原代码 → 6/6 全绿。
- 教学结论：测试测的是「守约 + 数据一致」，不是「通不通」；悄悄错（字段丢/被改/未落库）是人眼难发现、断言能抓的典型。

## 三、给「深入学习」新对话的上下文

- 项目本质：AI-TAE 不是「调 LLM 写 pytest」，而是一条把「AI 起草 + 机器门禁 + 人工审阅 + 持续回归」串起来的可复现流水线；核心哲学 = 不信模型输出，用本地校验/真实执行验证。
- 架构：核心（parser/codec/llm/generator/runner/cli/metrics/report）与被测通过「适配契约」（src/aiae/targets/）解耦；换项目只写适配器。
- 学习用文档：README（电梯陈述/亮点）、docs/AI-TAE-非技术介绍.md（通俗版）、docs/v1-technical-design.md（数据流/口径）、docs/progress-2026-09-04.md（方案 B 前因后果）。
- 关键文件（学习时对照代码读）：
  - src/aiae/parser/openapi.py（OpenAPI → Operation 归一化）
  - src/aiae/parser/codec.py（LLM 输出校验/落盘门禁）
  - src/aiae/generator/__init__.py（Prompt 构造 + 语义层限次重试）
  - src/aiae/runner/__init__.py（pytest 子进程 + conftest 按 auth_mode 渲染）
  - src/aiae/targets/base.py + todo_app.py + fastapi_crud_todo.py（适配契约）
  - src/aiae/healer/__init__.py（V2 自愈编排 + 护栏）

## 四、学习路线建议（按顺序）

1. HTTP 与 requests：看 data/generated_tests_fastapi_crud_todo_v3/*.py（真实生成用例 = 活教材），理解 准备→动作→断言；
2. pytest + junit：跑 `aiae run`，读 data/runs/ 下 junit 的 passed/failed/error 区分；
3. 端到端走查：`aiae generate`（调 DeepSeek，需 .env key）→ `aiae run`，对照 generator/runner 代码；
4. 适配层：读 targets/*，理解「换项目 = 写适配器」，可试加第三个被测项目；
5. V2 自愈：读 healer/__init__.py 的 KV→RAG→LLM→人工确认→真实验证→写回 与护栏设计；
6. 工程概念补课：断言精确性、契约测试、回归、LLM 成本/幻觉/门禁、RAG、黑盒 vs 白盒。
