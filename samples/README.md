## 为什么必须先定被测项目

- V1 生成的是**针对真实 API** 的 pytest 用例，需要真实可运行的被测服务；
- 面试官会点开仓库、clone 被测项目复现 —— 必须真实、能本地跑、可复现。

## 选择标准（满足越多越好）

1. 开源、仓库小、本地一条命令能跑起来；
2. 是 **Web 应用**，含 登录/表单/列表/增删改查 等典型可测元素（V2 自愈需要 UI）；
3. **自带 OpenAPI/Swagger**（如 FastAPI 自动生成 `/openapi.json`），或能低成本生成 ——
   V1 直接吃接口文档，不必手工造；
4. 有稳定版本可固定（记录 commit），避免页面/接口“自己乱动”干扰评测；
5. 技术栈不限，但 Python/FastAPI 类最省事（本人熟悉，好讲）。

## 候选方向（具体仓库名待你确认后锁定）

- 方向 A：一个 FastAPI 编写的“待办/图书管理”类小应用（自带 OpenAPI，最顺）
- 方向 B：某个知名的轻量开源 Web 应用（满足上述标准，能讲清“为什么选它”）

## 确认后要做的事

1. 固定被测项目 commit / 版本；
2. clone 到 `samples/<project>/`（或另建目录，**不入库**被测项目本身，只记录地址+commit）；
3. 导出其 OpenAPI 到 `samples/openapi/`，作为 V1 的输入样例。
